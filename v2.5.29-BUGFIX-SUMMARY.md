# v2.5.29 - Bug Fixes Summary

## 🐛 Bugs Fixed

### Bug #1: Wastage Charge Disable Not Saving ✅ FIXED
**Problem:** When unchecking "Enable Wastage Charge" and saving, the checkbox would still be checked when reopening the edit modal.

**Root Cause:** JavaScript was sending `enable_wastage_charge: 0` when unchecked, but PHP AJAX handler uses `isset()` which returns true even for 0.

**Fix:** Changed JavaScript to only send the parameter when checkbox is checked:
```javascript
// BEFORE (WRONG):
enable_wastage_charge: $('#edit_enable_wastage_charge').is(':checked') ? 1 : 0

// AFTER (CORRECT):
if ($('#edit_enable_wastage_charge').is(':checked')) {
    formData.enable_wastage_charge = 1;
}
// If unchecked, parameter is not sent at all
```

**Result:** Now when you uncheck and save, the setting is properly saved as disabled (0).

---

### Bug #2: Misleading "Percentage" Label ✅ FIXED
**Problem:** Table showed "✓ Percentage" for Making Charge, but it's actually calculated per-gram, not as a percentage.

**Root Cause:** Display code showed `making_charge_type` from database which was "percentage", but the actual calculation uses per-gram pricing.

**Fix:** Changed display logic to show accurate charge type:
```php
// BEFORE:
<?php echo esc_html(ucfirst($group->making_charge_type ?? 'percentage')); ?>

// AFTER:
<?php 
$making_type = $group->making_charge_type ?? 'percentage';
if ($making_type === 'percentage') {
    echo 'Per Gram';  // More accurate description
} else {
    echo esc_html(ucfirst($making_type));
}
?>
```

**Result:** Now shows "✓ Per Gram" which accurately reflects how making charges are calculated.

---

### Bug #3: Disabled State Not Visually Clear ✅ FIXED
**Problem:** When a charge was disabled, it showed "✗ Disabled" but the red X wasn't very visible.

**Fix:** Changed the red color to WordPress standard error red:
```php
// BEFORE:
<span class="dashicons dashicons-no" style="color: red;"></span>

// AFTER:
<span class="dashicons dashicons-no" style="color: #dc3232;"></span>
```

**Result:** Disabled state is now more visually distinct with proper WordPress error color.
